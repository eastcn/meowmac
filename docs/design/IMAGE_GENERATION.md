## 快速接手

1. 先读本指南。猫的调研依据和修改过程见 [v0-2-cat-research.md](v0-2-cat-research.md)。应用规则见 `SPEC.md` 和 `../DECISIONS.md`，执行状态以当轮 relay 的 `plan.md` 为准。
2. 找到用户指定的造型底稿，用 `view_image` 查看。新图形先确认参考图、用途、风格和实际显示尺寸。
3. 调用当前宿主的 imagegen Skill，优先使用内置生成工具。本轮使用的都是内置工具，不需要 API 密钥，也没有使用 CLI。
4. 修改已认可的图时，作为编辑任务处理。传入准确的底稿，只改本轮指定的部分。
5. 检查结果，另存带版本号的文件。保留已认可版本，记录输入、完整提示词、输出和用户反馈。
6. 项目要继续引用的图片和提示词，放在仓库内。默认生成目录、系统临时目录和忽略的验收目录都不能作为唯一接手来源。

本轮提示词已从 `build/acceptance/` 复制到 [cat/prompts/](cat/prompts/)。这个目录包括圆润调整过程的提示词，以及一次尚未通过动画验收的五帧试验。提示词是复用起点，再次生成仍需查看结果。

## 造型经验

先让形象成立，再做配色和动作。最初两版用程序拼圆块和移动腿，身体像块状物，腿部连接生硬。参考真实的逐帧素材后，再用 imagegen 探索原创轮廓，得到用户认可。

猫在小尺寸下依靠尖耳、短口鼻、合适的头身比、尾巴和腿间空隙被识别。不要用巨大的头眼、过细的线条或密集毛发来补救轮廓。参考 RunCat 时只借鉴运动和辨识规律，保持原创形象，遵守 D4。

“圆润”要调整全身比例。第一版只增加胸腹饱满度，用户觉得像加了肚子。第二版一起缩短躯干、腿和颈部，但太胖。第三版保留紧凑比例，再均匀收瘦胸腹和肩胯，用户认可。

比例反馈要写成能执行的局部修改，例如“保留短腿，收瘦胸腹和肩胯”，同时列出不变项。提示词中的百分比只是调整意图，不是对生成结果的实测值。

上色单独做。锁定轮廓、比例、跑姿和构图，只改底色、斑纹和必要的面部细节。小图优先用有限配色和较宽的花纹；放大图好看后，仍要检查缩小后的表现。

## 可复用的提示词结构

以后做其他形式的图形，也先明确用途和不变项。简单几何图、工程图和现有矢量素材的小修改，可按实际需求用原生工具；角色造型、插画和位图配色探索可用 imagegen。

```text
用途：图片放在哪里，实际显示尺寸是多少。
输入：哪张是编辑目标，哪张只供风格或动作参考。
本轮修改：具体改哪些形状、颜色或姿态。
保持不变：角色身份、轮廓、比例、朝向、动作、构图。
画法：剪影或平涂，配色与细节密度。
背景：造型评审用白底，应用资产需要真实透明背景。
避免：额外角色、文字、场景、阴影，以及该任务出现过的问题。
输出：一张造型，或明确数量和排列方式的动作研究稿。
```

新角色先出单帧，不同时要求配色、整套动画和应用实现。用户认可后，每轮围绕一个目的修改；涉及胖瘦时，胸背、肩胯和四肢要一起检查协调性。

## 从造型到应用资产

当前四张图都是白底评审稿，不能直接当透明菜单栏帧。生成透明版本时，明确要求真实透明背景，并检查透明通道和可见内容范围。RGBA 格式、生成成功和包围盒检查都不能代替视觉验收。

本轮黑色透明图在预览中不易辨认，因此又生成白底查看副本。两者未经像素一致性验证。后续应保留透明源，并用受支持的显示方式检查它在浅色、深色背景上的表现。

连续帧必须保持同一角色、画布尺寸、绘制尺度和定位。跑动包含躯干伸展与收拢、前后腿相位和尾巴跟随，不能只移动腿。彩色帧还要保持斑纹跟随同一身体部位，避免逐帧换花纹。

五帧研究稿存在首尾姿态过近、位置和边距不统一的问题，未验收。后续要校正帧序、首尾循环和基线，再用实际播放检查；不要根据静态帧图宣称动画通过。

后续制作了 [标准瘦身五帧 v2](cat/animation/slim-run-sheet-v2.png)，明确区分末帧蹬地和首帧伸展。[完整提示词](cat/prompts/slim-run-sheet-v2.txt)与[取帧定位](cat/animation/slim-run-v2-layout.json)已保存。试播共用画布和绘制尺度，对齐头部，不把不同姿态分别缩放到相同宽度。预览控制已验证，动作仍待用户确认；这是接手时可继续检查的样稿，不是已验收资产。

菜单栏当前规范的显示高度为 18 pt。后续验收要覆盖原尺寸、深浅色、不同负载速度、提醒和严重状态，以及减少动态效果。角色配色与状态表达的关系须写进执行计划，仍按 D11、D12 和 SPEC 处理，不能让更换猫配置改变健康判定规则。
