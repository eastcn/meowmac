# 布局与显示合同

本文件记录布局文件合同。v1 的标签页与功能块规则继续适用；2026-10-03 起，写入使用 v2，并把总览条并入同一布局。

## 范围

布局控制总览条四格、三个标签页的顺序、页内功能块顺序和显示开关。隐藏只影响展示，保持现有采集、额度刷新、存储统计和健康判定路径。

| 标签页 | 功能块 id 与默认顺序 | 可隐藏 |
| --- | --- | --- |
| 系统 | `system.chart`、`system.energy`、`system.disk` | 后两项 |
| 额度 | `quota.trend`、`quota.cost`、`quota.storage` | 全部 |
| 网络 | `network.checks`、`network.sites`、`network.egress` | 全部 |

总览条至少保留一格，底部操作栏和三个标签页保留。能耗诊断有问题时固定在系统页最前；系统趋势常驻（D30）。额度页的渠道切换、采集错误、账号、窗口和可重置次数保持原位置与出现条件；网络结论、检测时间和立即复测固定在网络页最前。

功能块的数据条件保持现有行为。例如没有花费或存储数据时，该块仍不出现。配置窗口始终列出完整清单，允许提前调整尚无数据的块。隐藏块仍保留在排序数组中，恢复显示时回到保存的位置。

## 布局对象

下例是旧 v1 格式，只用于读取。保存时写入 v2，增加 `overview`，其余字段和值保持原规则。

```json
{
  "schemaVersion": 1,
  "tabs": ["system", "quota", "network"],
  "cards": {
    "system": [
      {"id": "system.chart", "visible": true},
      {"id": "system.energy", "visible": true},
      {"id": "system.disk", "visible": true}
    ],
    "quota": [
      {"id": "quota.trend", "visible": true},
      {"id": "quota.cost", "visible": true},
      {"id": "quota.storage", "visible": true}
    ],
    "network": [
      {"id": "network.checks", "visible": true},
      {"id": "network.sites", "visible": true},
      {"id": "network.egress", "visible": true}
    ]
  }
}
```

应用默认布局在该对象上增加下列字段，并将 `schemaVersion` 设为 `2`：

```json
"overview": {
  "order": ["cpu", "memory", "quota", "network"],
  "hidden": [],
  "quota": {"provider": "claude", "window": "minutes:300"}
}
```

v1 读取后在内存中补上此默认总览条。仅显式保存时才写成 v2，不自动改写本机文件。`order` 必须恰好包含四个格子 id 各一次；`hidden` 只能包含这四个 id，不能重复或隐藏全部。`provider` 只能是 `claude`、`codex`、`deepseek`、`opencodego`。`window` 只接受 `auto`、正整数 `minutes:<N>` 或非空 `id:<标识>`。同时长的多个窗口用 `id:` 区分。所选窗口暂缺时保留配置，总览额度格显示“—”。

所有对象严格检查字段；版本是有限整数，布尔值不能代替版本。`visible` 必须是 JSON 布尔值。

`tabs` 必须是三个标签页的完整排列。`cards` 恰好包含三个标签页；每个数组必须是该页三个 id 的完整排列。拒绝缺项、重复、未知 id、跨页 id 和错误类型。`system.chart.visible` 必须为 `true`。不接受空页数组，也不接受脚本、数据源、路径或健康阈值字段。

网络或额度的三个可选块全部隐藏是合法布局；固定内容仍显示。标签页不能隐藏，页内不能跨页拖动。

## 猫包兼容

v1 的清单、字段和文件合同保持 [CAT_FORMAT.md](CAT_FORMAT.md) 的原规则。v1 的包内布局视为应用默认布局。

v2 的清单只在 v1 根字段上增加 `panel`，并把根 `schemaVersion` 改为 `2`。根字段恰好为 `schemaVersion`、`id`、`name`、`run`、`severe` 和 `panel`；`panel` 是完整布局对象，不能省略。布局对象自己的版本可为 `1` 或 `2`；无效的 `overview` 拒绝整个猫包。

图片、几何、名称、id、清单 64 KiB、图片 8 MiB、单包 20 MiB 和目录最多三个普通文件的限额沿用 v1。不增加布局文件；布局在 `manifest.json` 内。未知版本或无效 `panel` 拒绝整个导入，不静默导入帧图。不修改四个内置 v1 清单或认可 PNG。

旧版 MeowMac 不支持 v2 包，这是包版本的显式差异。新实现必须同时接受 v1 和 v2；不自动升级或重写已有包。

## 本机布局

运行目录为 `~/Library/Application Support/MeowMac/PanelLayouts/`。每只猫使用 `<id>.json`，包括 `builtin.slim` 等内置 id。id 校验沿用猫包规则；文件名由已验证 id 生成，不能接受外部路径。

文件对象恰好包含 `schemaVersion: 1`、`catID` 和 `layout`。`catID` 必须等于文件对应的猫 id；`layout` 是上面的完整布局对象。文件不超过 16 KiB，只接受普通文件。读取和写入拒绝已发现的符号链接，不跟随链接读取或写入其他目录。

生效顺序：合法的本机布局、包内布局、应用默认布局。包内布局来自已通过校验的包；v1 使用应用默认布局。缺少本机文件是正常情况，不创建目录、不写默认文件。

有效猫不可用、只能显示应急矢量猫时，面板使用应用默认布局；配置窗口入口禁用。没有经过校验的猫 id 时不得保存本机布局。

内置资源、导入源目录和受管理猫包均不因窗口保存而改写。原包可以分享其默认布局；本机修改的导出入口留到后续轮次。本轮不增加导出、删除、覆盖导入包或全局布局入口。

## 保存与恢复

窗口打开时固定编辑当时有效猫的 id，草稿来自当前生效布局。页内拖动、标签页拖动、显示开关和恢复默认只改草稿。“恢复默认布局”使用该猫的包内默认布局，v1 使用应用默认布局。

保存先校验完整草稿，再在 `PanelLayouts` 的同一目录创建独占暂存文件，写完并同步文件，然后原子替换该猫的普通布局文件。通过固定父目录句柄完成 I/O，拒绝符号链接目录；失败只清理本次暂存文件。沿用第一轮目录访问边界，不能借此写包外或仓库外测试目录。

原子替换成功是发布点。此后将已保存布局发布到面板并关闭窗口；不重新采集系统、额度或网络。目录同步失败须单独记录，不能报告成“写入前失败且旧磁盘文件未变”。本轮不承诺断电恢复。

发布前写入失败时，保持旧生效布局与窗口草稿，窗口留在原处并显示错误。取消或关闭窗口放弃草稿，不写文件。

成功切猫或成功导入并切换后，关闭原编辑窗口并放弃草稿；新猫显示自己的布局。切猫或导入失败时，原窗口、草稿和旧布局均保留。重复打开只激活现有窗口，不创建多个写入者。每次保存绑定打开时的猫 id；猫 id 已改变的迟到保存请求必须拒绝。

本机布局损坏、未知版本、错猫 id 或非普通文件时，保留原文件并回退包内默认布局；读取失败不切回标准瘦身，也不改变猫动画、其他猫的布局和健康判定。设置窗口显示恢复原因。

保存前须重读已有布局文件。已有文件无效或不安全时拒绝覆盖，保留草稿与原文件，提示通过现有配置目录入口检查文件。本轮不自动修复或删除坏文件。正常文件的显式保存可以原子替换。

## 面板行为

标签页身份仍是 `PanelTab`，排序不改变健康问题的归属。页状态点按身份匹配。D17 的问题优先打开与正常时记住上次标签页保持原规则；不得用排列下标保存或跳转。

可配置功能块由同一 id 清单校验和生成。实际面板通过 `Card` 接口渲染；固定内容保留各页原有入口。功能块不允许重复挂载、跨页显示或加载任意类型。

只在实际显示的相邻分节之间画分隔线；隐藏或无数据时不留下孤立分隔线与空白占位。配置改变后重新测量内容高度，保持 360 pt 面板宽度和最高 820 pt。窗口设计稿宽 520 px，对应原生窗口内容宽 520 pt；高度随内容与原生控件实际尺寸调整。

健康规则保持不变。隐藏异常项仍显示相应总览告警和页状态点；点击总览问题仍能打开对应标签页。总览条格子的顺序、显示和额度来源取当前生效布局。网络只读取现有公开数据，不修改 TunCanary。

同一生效布局驱动面板、设置窗口、合成渲染和诊断快照。快照增加有效布局与是否回退的信息，不记录本机文件路径、原文件内容或外部来源。离线测试直接使用真实启动初始化与切猫入口，不调用实时快照采集。
