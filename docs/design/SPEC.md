# MeowMac 设计规范

本文是 v0.1 视觉返工的实现依据，2026-09-30 由用户确认定稿。终稿按 D39 合成：版式取 GPT 的独立设计稿（`docs/design/gpt/`，只作参考），状态规则、菜单栏猫和设置菜单取原画布。

设计稿源文件在 `docs/design/mockups/`，每个 `.dc.html` 是一个画板，元素的尺寸、颜色和间距都写在 inline style 里，数值以设计稿为准。`<script>` 里 `renderVals()` 返回的是示例数据，都是虚构的。

| 画板 | 内容 |
| --- | --- |
| `Main.dc.html` | 系统页，正常状态 |
| `Alert.dc.html` | 系统页，提醒状态（失控进程、阻止休眠、建议降温） |
| `QuotaCodex.dc.html` | 额度页，Codex 渠道，完整长度 |
| `QuotaClaude.dc.html` | 额度页，Claude 渠道，完整长度 |
| `Network.dc.html` | 网络页，完整长度 |
| `Settings.dc.html` | 点开“设置”后的菜单 |
| `MenuBar.dc.html` | 菜单栏猫的帧和三种状态 |

设计稿用 HTML 模拟，实现用 SwiftUI 和 AppKit。下面写的是从设计稿到实现的对应规则，设计稿里没画到的情况也以本文为准。

## 面板

- 容器是 `NSPopover`，宽 360pt，高度随内容变化，最高 820pt。总览、标签页和底部操作栏固定，中间的标签页内容超出时滚动。
- 面板高度 = 固定部分的实际高度 + min(标签页内容的实际高度, 820 − 固定部分的实际高度)。两个高度都要实际测量，不能写死。切换标签页或内容变化时，面板跟着变高或变矮。
- 打开面板时，任何控件都不显示焦点框。
- 左右内边距 16pt。分节之间 12pt，用 1pt 的分隔线隔开。
- 正常状态的系统页要在 820pt 内完整显示趋势图、能耗排行和磁盘。提醒状态的系统页、额度页和网络页允许滚动。
- 深色模式不单独出图。所有颜色都用系统语义色或本文定义的成对颜色，深色模式自动适配。

## 材质：液态玻璃

用 macOS 26 SDK 编译，`NSPopover` 会自动得到系统的液态玻璃外观。正文区域不再叠加玻璃卡片，只有下面这些元素用玻璃：

| 元素 | macOS 26 及以上 | macOS 14～15 |
| --- | --- | --- |
| 渠道按钮、重置次数卡片 | `glassEffect`，圆角 12pt | `.thinMaterial` 背景，加 1pt 白色描边，不透明度 0.6 |
| 能耗诊断卡片 | 橙色着色的玻璃，圆角 12pt | `systemOrange` 10% 的底色，加 1pt `systemOrange` 30% 的描边 |
| 标签页分段控件、时间范围切换 | 胶囊形玻璃轨道，选中项是实色胶囊（不要玻璃叠玻璃） | 胶囊形轨道用 `quaternarySystemFill`，选中项用白色胶囊加阴影 |
| 胶囊按钮（清理、立即复测、底栏的刷新和设置） | 胶囊形玻璃按钮 | 胶囊形 `.bordered` 按钮 |

判断系统版本用 `#available(macOS 26, *)`。设计稿里的淡紫色底只是模拟桌面透过来的效果，不要画渐变壁纸。

总览的 4 个指标平铺，不加卡片背景。“在访达中显示”是链接样式的文字按钮，不用胶囊。

## 颜色

| 用途 | 颜色 |
| --- | --- |
| 正文、标题 | `labelColor` |
| 说明文字、坐标轴、表头 | `secondaryLabelColor` |
| 分隔线 | `separatorColor` |
| 横线和柱状图的底 | `quaternarySystemFill` |
| 状态：正常、提醒、严重（横线、状态点、图标） | `systemGreen`、`systemOrange`、`systemRed` |
| 状态色的文字（如“剩余 30%”“通过”） | 成对颜色：浅色模式用加深的版本，绿 `#1E8E3E`、橙 `#B25000`、红 `#D70015`；深色模式直接用 `systemGreen`、`systemOrange`、`systemRed` |
| 趋势图：CPU、内存已用、整机功耗、电池温度 | `systemBlue`、`systemPurple`、`systemTeal`、`systemPink` |
| 温度偏高的时段 | `systemOrange` 16% 的底色带 |
| 节奏刻度、匀速用完的虚线 | `systemRed` |
| 额度用量曲线、5 小时峰值柱、花费柱 | `systemBlue`：曲线实色，峰值柱 60%，花费柱 35%，今天的花费柱实色，进行中的峰值柱 28% |
| 本地存储分段：会话、缓存、其他 | `systemBlue`、`systemTeal`、`systemPurple` |
| 磁盘横线 | `systemGray`；可用空间低于 10% 时 `systemOrange` |

颜色只表示状态：CPU 的横线固定是蓝色，其余横线的颜色都表示状态，不用渠道色。

## 字号

字体用系统字体（SF Pro，中文 PingFang SC），数字一律用等宽数字（`monospacedDigit()`）。IP 地址用等宽字体（`.monospaced`）。

| 字号 | 用途 |
| --- | --- |
| 22pt 半粗 | 花费金额 |
| 20pt 半粗 | 总览指标的数值、磁盘可用量 |
| 15pt 半粗 | 总览状态行、渠道名、窗口剩余百分比、网络结论 |
| 13pt 半粗 | 分节标题、窗口名、诊断和检查项的名称、趋势图的当前值 |
| 13pt 常规 | 表格行（能耗排行、站点连通性、出口 IP） |
| 12pt | 胶囊按钮、“在访达中显示” |
| 11pt | 说明文字、指标标签、图例 |
| 10pt | 坐标轴、趋势图量程、指标副信息、表头 |

## 总览

**状态行**：左边是小猫图标，形状同菜单栏猫的第 1 帧，颜色同当前状态（正常用 `labelColor`，提醒橙色并带速度线，严重换成红色趴姿）。

- 正常：显示“一切正常”，右侧是刷新时间，如“1 分钟前”。
- 提醒或严重：显示“提醒 · 最严重的问题 ›”，“提醒”用橙色文字，“严重”用红色文字。整行可点击，跳到问题所在的标签页。
- 满足 D14 的“建议降温”条件（`thermalState` 为 fair 并持续 5 分钟）时，状态行下方多一行：“建议降温”橙色胶囊标签，后面写“另有 N 项问题，见系统页”（只有一个问题时省略后半句）。

**4 个指标**：4 列等宽，列间距 14pt。每列从上到下是标签（11pt）、数值（20pt 半粗）、副信息（10pt）和一条 3pt 的横线。

| 指标 | 标签 | 数值 | 副信息 | 横线 |
| --- | --- | --- | --- | --- |
| CPU | `CPU` | 使用率，如 `24%` | `整机负载` | 蓝色，长度等于使用率 |
| 内存 | `内存` | 已用百分比，如 `69%` | 已用和总量，取整，如 `11 / 16 GB` | 长度等于已用比例；颜色表示内存压力：正常绿，偏高橙，严重红 |
| 额度 | 渠道名，如 `Claude` | 剩余百分比，如 `72%` | 窗口和方向，如 `5 小时 · 剩余` | 长度等于剩余；颜色：剩余不低于 50% 为绿，20%～50% 为橙，低于 20% 为红 |
| 网络 | `网络` | 下行速率，如 `↓2.4M` | 上行速率，如 `↑128K` | 满长；颜色表示 TunCanary 结论：绿、橙、红 |

额度指标默认是 Claude 的 5 小时窗口，v0.2 可在猫配置中更换。速率单位是每秒字节，按大小显示为 `B`、`K`、`M`、`G`，保留一位小数，不写 `/s`。

## 标签页

胶囊形分段控件，包含系统、额度、网络三项，选中项必须一眼能看出来：轨道用玻璃，选中项用实色胶囊加半粗字，不要玻璃叠玻璃。每项文字前有一个 6pt 的状态点，颜色表示这一页最严重的状态。打开面板时，默认显示问题最严重的一页；都正常时显示上次看的一页（D17）。

## 系统页

从上到下：

1. **能耗诊断**：只在有问题时出现，并排在最前面（见 `Alert.dc.html`）。橙色玻璃卡片，标题“能耗诊断”，右侧写问题数。每个问题一行，行之间有分隔线：
   - 左边：7pt 状态点、进程名（13pt 半粗），下面一行写问题类型，如“失控进程 · 占满 1 个核心”“阻止系统休眠”“内存压力持续偏高”。
   - 右边：数值（13pt 半粗，状态色文字），如 `98%`、`3 小时 12 分`；下面一行写持续时长或开始时间，如“已持续 35 分钟”“从 11:23 开始”。持续时长从判定开始计时，不能显示成“0 分钟”。
   - 卡片最后一行：“建议用 AI 诊断：把进程名和上面的数值交给 AI 助手排查”。
   - 严重级别的问题，状态点和数值用红色。
2. **系统趋势**：标题“系统趋势”，右侧是“15 分钟”和“1 小时”的切换。4 个量各占一行：上面一行是 6pt 色点、名称、量程（如 `0–16 GB`）和靠右的当前值；下面是占满整行宽度、高 26pt 的折线。4 条折线共用一条时间轴，只在最下面显示 3 个刻度，写实际时刻，如 `14:20`、`14:28`、`14:35`。
   - 量程：CPU 固定 0–100%；内存 0 到物理内存总量；功耗 0 到 40 W，峰值超过时向上取整到 10 W；温度取窗口内的最低和最高值，向外取整到 2 °C。
   - `thermalState` 为 fair 或更高的时段，在 4 行的同一位置画橙色底色带。内存那条折线下方有浅色填充。
   - 图例一行：左边是底色带的色块和说明，正常时写“热状态 fair 及以上的时段”，提醒时写“热状态 fair 已持续 N 分钟，达到‘建议降温’条件”；右边写“同一时间轴 · 各自纵轴”。
3. **能耗排行**：标题右侧写“前 5 名”。表头是“进程”“CPU”“影响分”（10pt）。每行高 21pt：序号（11pt，说明色）、进程名、CPU 百分比、能耗影响分。被能耗诊断列出的进程，整行用橙色半粗文字。
4. **磁盘**：一行里依次是“磁盘”、可用量（20pt 半粗，如 `186`）加“GB 可用”、靠右的“清理…”按钮；下面是一条 6pt 的横线（长度等于已用比例）；再下面左边写“已用 326 GB”，右边写“共 512 GB”；最后一行写“上次清理：9 月 28 日 · 释放 8.4 GB”。

## 额度页

从上到下（见 `QuotaCodex.dc.html` 和 `QuotaClaude.dc.html`）：

1. **渠道切换**：4 个等宽的玻璃按钮。每个按钮从上到下是渠道 logo（20pt）、渠道名（11pt，选中时半粗）、一条 3pt 的迷你横线和剩余百分比（11pt 半粗，状态色文字）。按钮上显示这个渠道**剩余最少的窗口**，颜色规则同总览的额度指标。
   - logo 用 CodexBar.app 自带的 `ProviderIcon-{claude,codex,deepseek,opencodego}.svg`（在 `/Applications/CodexBar.app/Contents/Resources/`），拷进 MeowMac 的资源目录，渲染成模板图。这些 logo 是各公司的商标，README 里要注明。设计稿里的字母圆点只是占位。
2. **账号**：第 1 行是渠道名（15pt 半粗）、套餐胶囊（CLI 返回了才显示）和靠右的“14:32 更新”；第 2 行是账号邮箱和靠右的“来源 oauth”。
3. **窗口**：每个窗口一组。
   - 第 1 行：窗口名（13pt 半粗），靠右是“剩余”（11pt）和百分比（15pt 半粗）。百分比在绿档时用 `labelColor`，橙档和红档用状态色文字。
   - 一条 6pt 的横线，长度等于剩余，颜色规则同总览的额度指标。横线上有一条 2×12pt 的红色刻度，位置是“按节奏此刻应该剩多少”。
   - 第 2 行：一个红色小刻度、“按节奏应剩 49%”，靠右是重置时间，如“10/4 00:58 重置”。
   - 第 3 行：节奏说明。不会提前用完时写“节奏正常，可以撑到重置”（说明色）；会在重置前用完时写“比节奏快 19 个百分点，约 1 天 12 小时后用完”（橙色文字）。
4. **重置次数**：CLI 返回的 `codexResetCredits.availableCount` 大于 0 时显示一张玻璃卡片，写“可重置限额 N 次”和各次的过期日期。目前只有 Codex 有。
5. **用量趋势**：数据来自 MeowMac 自己的额度历史（D7）。
   - 长周期窗口（7 天、每周）每个窗口一张图，画**当前这一轮**：横轴从上次重置到下次重置，纵轴是已用 0～100%。蓝色折线加浅色填充，从本轮开始画到现在，末端一个圆点；现在的位置画一条竖线。红色虚线从左下角连到右上角，表示匀速用完的节奏。图上方写“每周窗口 · 从重置到重置，累计已用”和靠右的“已用 70%”；图下方的刻度写“9/27 重置”“现在”“10/4 重置”；图例写“匀速用完的节奏：曲线在虚线上方就是用得偏快”。
   - 有 5 小时窗口的渠道，再加一行柱状图：最近 7 天，每根柱是一个窗口里的最高已用百分比，高 40pt。超过 80% 的柱是橙色，进行中的窗口是浅蓝色。上方写“5 小时窗口 · 每个窗口的最高已用”，下方是 3 个日期刻度和图例。不要把 5 小时窗口画成折线。
6. **花费**：只有 Claude 和 Codex 有。标题右侧注明“按 token 估算，不是账单”。两列：今天、近 30 天，每列是标签、金额（22pt 半粗）和 token 数。下面是 30 天的柱状图，高 40pt，今天那根实色；刻度写“9/1”和“今天”；最后一行是“最常用模型”和模型名。
7. **本地存储**：标题后面是目录（如 `~/.codex`，说明色），靠右是总大小。下面是一条 6pt 的分段横线，段之间留 2pt；图例写会话、缓存、其他的大小；最后一行写会话文件数和靠右的“在访达中显示 ↗”。
   - 分段规则：会话是 Codex 的 `sessions`、`archived_sessions` 和 Claude 的 `projects`、`sessions`；缓存是两者的 `cache`，加上 Claude 的 `file-history`；其余都算其他。
   - 只统计文件大小，不读取任何文件的内容（目录里有 `auth.json` 这类凭据文件）。**不提供删除功能**。
   - 统计在后台进行。每次打开额度页时，如果距上次统计超过 10 分钟，就重新统计。

### 节奏的计算

刻度和节奏说明由 MeowMac 自己算，不依赖 CLI 的 `pace` 文字：

- 窗口长度 `L` 取 CLI 返回的窗口时长；没有时按窗口名推断：5 小时窗口 5 小时，7 天和每周窗口 7 天。重置时间为 `R`，现在为 `T`，已用比例为 `u`。
- 已过比例 `e = 1 − (R − T) / L`。刻度位置和“按节奏应剩”都是 `1 − e`。
- 差值 `u − e` 的单位是**百分点**，文案写“比节奏快 N 个百分点”。
- 用完时间 = `(1 − u) ÷ (u ÷ 已过时长)`。早于 `R` 时显示“约 X 后用完”并判为提醒（D13）；否则显示“节奏正常，可以撑到重置”。
- `L` 或 `R` 拿不到时，隐藏刻度和节奏说明，不显示占位文字。

## 网络页

MeowMac 自己画，不嵌入 TunCanary 的弹窗。数据来自 TunCanary 的 `AppModel`：`overall`、`local`、`siteHistory`、`egressResults`、`egressState`、`lastCheckedAt`。

1. **结论**：第 1 行是 32pt 的状态图标（绿色对勾、橙色感叹号或红色叉）、结论文字（15pt 半粗）和一句说明，如“DNS 走代理 · 5 项检查通过”。第 2 行左边写“1 分钟前检测”，右边是“立即复测”按钮，调用 `MonitorController.recheck()`。
2. **连接检查**：标题右侧写“5 / 5 通过”。5 项各两行：代理 TUN、VPN、主网络 DNS、代理 DNS、Tailnet。第 1 行是 7pt 状态点和名称（13pt 半粗），第 2 行是一句说明（11pt），右边是状态文字（“通过”，或者异常时的橙色、红色文字）。
3. **站点连通性**：标题右侧写“最近 5 轮”。表头是“目标分组”“通过”“延迟中位数”。国内、海外、子网目标各一行，通过数用状态色文字，延迟后面跟说明色的 `ms`。
4. **出口 IP**：标题右侧写采样间隔。每个探测目标两行：第 1 行是目标名和靠右的 IP（13pt 半粗，等宽字体）；第 2 行是地区和靠右的“12 天未变”。

如果某个字段在 TunCanary 外面读不到，就跳过这一项，写进 result；不要修改 TunCanary。

## 底部操作栏

左边是“刷新”胶囊按钮（带图标），中间是“额度更新于 14:32”，右边是“设置”胶囊按钮（齿轮图标加下拉箭头）。

点“设置”弹出原生 `NSMenu`（macOS 26 上自动是液态玻璃），菜单项见 `Settings.dc.html`：打开配置文件…、在访达中显示配置目录、分隔线、猫配置（置灰，右侧写“暂未开放”）、开机启动（打勾表示开启）、分隔线、关于 MeowMac、退出 MeowMac（⌘Q）。

## 菜单栏猫

猫的矢量路径以 `MenuBar.dc.html` 里 `run()` 和 `lying` 的定义为准，画布坐标是 44×28，菜单栏里的高度为 18pt。

| 状态 | 图 | 动画 |
| --- | --- | --- |
| 正常 | 5 帧奔跑，模板图，跟随菜单栏深浅色 | 帧间隔 = 0.5 − 0.45 × 负载（秒），即 0.5 秒到 0.05 秒 |
| 提醒 | 同样的 5 帧，**整只猫为 `systemOrange`**，彩色图 | 速度仍然只看负载，不因为提醒而加快 |
| 严重 | 趴姿单帧，`systemRed`，彩色图，头上有“zz” | 停止 |

负载不低于 0.7 时，在猫身后画三道速度线，颜色和猫一致，正常和提醒状态都适用。规则是：颜色表示状态，速度表示负载。系统开启“减少动态效果”（`NSWorkspace.shared.accessibilityDisplayShouldReduceMotion`）时，定格在第 1 帧。

## 视觉验收

执行者要用 `MEOWMAC_RENDER_DIR` 渲染出下面这些预览图，逐张和设计稿对照，发现不一致就修改，然后重新渲染，直到一致为止：

- 系统页的正常和提醒状态、额度页的 Claude 和 Codex、网络页，浅色和深色各一张；
- 设置菜单打开时的截图或渲染图；
- 菜单栏猫：5 帧，外加提醒、严重和带速度线的帧。

对照时逐项检查：

1. 元素的顺序和分组与设计稿一致，没有多出或缺少的元素。
2. 尺寸、间距、圆角与设计稿的偏差不超过 2pt。
3. 字号和字重符合本文的字号表。
4. 360pt 宽度下没有文字被截断、重叠或溢出。
5. 正常状态的系统页在 820pt 高度内，能完整看到趋势图、能耗排行和磁盘。
6. 深色模式下所有文字都清楚可读，状态色文字用的是本文定义的成对颜色。
