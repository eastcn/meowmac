# MeowMac 设计规范

本文是 v0.1 视觉返工的实现依据，2026-09-30 由用户确认定稿。设计稿源文件在 `docs/design/mockups/`，每个 `.dc.html` 是一个画板，元素的尺寸、颜色和间距都写在 inline style 里，数值以设计稿为准。画板里的数据都是示例。

| 画板 | 内容 |
| --- | --- |
| `Main.dc.html` | 系统页，也是打开面板时的默认页 |
| `Quota.dc.html` | 额度页，完整长度 900pt，面板里超出的部分滚动 |
| `Network.dc.html` | 网络页 |
| `Alert.dc.html` | 提醒状态下的系统页，以失控进程为例 |
| `Settings.dc.html` | 点开“设置”后的菜单 |
| `MenuBar.dc.html` | 菜单栏猫的帧和三种状态 |

设计稿用 HTML 模拟，实现用 SwiftUI 和 AppKit。下面写的是从设计稿到实现的对应规则，设计稿里没画到的情况也以本文为准。

## 面板

- 容器是 `NSPopover`，宽 360pt，高度随内容变化，最高 820pt。总览条、标签页和底部操作栏固定，中间的标签页内容超出时滚动。
- 左右内边距 16pt，分节之间 14pt，分节之间用 1pt 的分隔线。
- 深色模式不单独出图。所有颜色都用系统语义色，深色模式自动适配。

## 材质：液态玻璃

用 macOS 26 SDK 编译，这样 `NSPopover` 会自动得到系统的液态玻璃外观。面板内部的玻璃元素按系统版本分两种写法：

| 元素 | macOS 26 及以上 | macOS 14～15 |
| --- | --- | --- |
| 指标块、卡片、渠道按钮、重置次数卡片 | `glassEffect`，圆角 12pt（卡片 14pt） | `.thinMaterial` 背景，加 1pt 白色描边，不透明度 0.6 |
| 标签页分段控件、时间范围切换 | 胶囊形玻璃轨道，选中项是凸起的玻璃胶囊 | 胶囊形轨道用 `quaternarySystemFill`，选中项用白色胶囊加阴影 |
| 按钮（清理、立即复测、在访达中显示） | 胶囊形玻璃按钮 | 胶囊形 `.bordered` 按钮 |

判断系统版本用 `#available(macOS 26, *)`。不要为了模拟玻璃效果去画渐变壁纸，设计稿里的淡紫色底只是用来模拟桌面透过来的效果。

## 颜色

| 用途 | 颜色 |
| --- | --- |
| 正文、标题 | `labelColor` |
| 说明文字、坐标轴 | `secondaryLabelColor` |
| 分隔线 | `separatorColor` |
| 进度条的底 | `quaternarySystemFill` |
| 状态：正常、提醒、严重 | `systemGreen`、`systemOrange`、`systemRed` |
| 联动图：CPU、内存、功耗、电池温度 | `systemBlue`、`systemTeal`、`systemOrange`、`systemPurple` |
| 节奏刻度线 | `systemRed` |

## 字号

字体用系统字体（SF Pro），数字一律用等宽数字（`monospacedDigit()`）。

| 字号 | 用途 |
| --- | --- |
| 15pt 半粗 | 总览条状态、指标块数值、渠道名、网络结论 |
| 13pt 半粗 | 分节标题、窗口名、剩余百分比 |
| 13pt 常规 | 列表行、按钮 |
| 11pt | 说明文字、指标块标签 |
| 10pt | 坐标轴、图例、指标块标签行右侧的次要数字 |

## 总览条

**第 1 行**：左边是小猫图标和当前状态。正常时显示“一切正常”，右侧是刷新时间；提醒时显示“提醒”（橙色），右侧可能出现“建议降温”胶囊标签；有问题时，下方多一张提醒说明卡片，写出最严重的问题和提示文案（见 `Alert.dc.html`）。

**第 2 行**：4 个等宽指标块，每块是标签行、数值和一条 3pt 的横线。

| 指标块 | 标签行 | 数值 | 横线 |
| --- | --- | --- | --- |
| CPU | `CPU` | 使用率，如 `42%` | 蓝色，长度等于使用率 |
| 内存 | 左边 `内存`，右边已用和总量，取整，如 `11/16G` | 已用百分比，如 `70%` | 长度等于已用比例；颜色表示内存压力：normal 绿，warn 黄，critical 红 |
| 额度 | 窗口名，如 `Claude 5h`；可在猫配置中更换（v0.2） | `剩 62%` | 长度等于剩余；颜色：剩余不低于 50% 为绿，20%～50% 为橙，低于 20% 为红 |
| 网络 | 左边 `网络`，右边上行速率，如 `↑320K` | 下行速率，如 `↓2.4M` | 满长；颜色表示 TunCanary 结论：绿、黄、红 |

速率单位是每秒字节，按大小显示为 `B`、`K`、`M`、`G`，保留一位小数，单位后面不写 `/s`。

## 标签页

胶囊形分段控件，包含系统、额度、网络三项，每项文字前有一个 6pt 的状态点，颜色表示这一页有没有问题。打开面板时，默认显示问题最严重的一页；都正常时显示上次看的一页（D17）。

## 系统页

从上到下：

1. **能耗诊断**：只在有问题时出现，并排在最前面。每行是状态点、进程名、问题类型、数值和持续时长（见 `Alert.dc.html`）。持续时长从判定开始计时，不能显示成“0 分钟”。
2. **联动图**：标题“负载、内存、功耗与温度”，右侧是 15 分钟和 1 小时的切换。4 条小图，每条高 30pt，左边 72pt 宽的一列写名称和当前值，右边是折线，4 条共用一条时间轴（只在最下面显示一次刻度）。热状态为 fair 或更高的时段，在 4 条图里画同样位置的橙色背景带。内存那条的折线下方有浅色填充。
3. **能耗排行**：前 5 名，每行是进程名、CPU 和能耗影响分，能耗影响分带一条小横条。
4. **磁盘**：剩余空间和百分比、一条 6pt 的横线、上次清理的时间和释放的空间，以及“清理…”按钮。

## 额度页

从上到下（见 `Quota.dc.html`）：

1. **渠道切换**：4 个玻璃按钮，每个是渠道 logo、渠道名和一条迷你用量条（颜色规则同总览条的额度块）。logo 用 CodexBar 仓库的 `Sources/CodexBar/Resources/ProviderIcon-{claude,codex,deepseek,opencodego}.svg`，拷进 MeowMac 的资源目录，渲染成模板图。这些 logo 是各公司的商标，README 里要注明。设计稿里的字母圆点只是占位。
2. **账号**：渠道名、套餐标签（CLI 返回了才显示）、账号邮箱、刷新时间和数据来源。
3. **窗口**：每个窗口是名称、剩余百分比、一条 8pt 的横线、节奏说明和重置时间。CLI 返回了 `pace` 时，在横线上画一条红色刻度，表示“按节奏此刻应该剩多少”，节奏说明写成“比节奏快 19%，约 1 天 12 小时后用完”或“节奏正常，可以撑到重置”。重置时间按当前真实时间计算。
4. **重置次数**：CLI 返回的 `codexResetCredits.availableCount` 大于 0 时显示一张卡片，写可重置次数和过期日期。目前只有 Codex 有。
5. **用量趋势**：最近 7 天。长周期窗口（如 7 天、每周）画折线，下方有浅色填充，并加一条从 0 到 100% 的红色虚线表示匀速用完的节奏。有 5 小时窗口的渠道再加一行柱状图，每根柱是一个窗口里的最高用量，超过 80% 的柱是橙色，进行中的窗口是浅蓝色。数据来自 MeowMac 自己的额度历史（D7）。
6. **花费**：只有 Claude 和 Codex 有。4 个数字：今天的金额、30 天的金额、今天的 token、30 天的 token；下面是 30 天的柱状图，今天那根高亮；再下面是最常用的模型。标题右侧注明“按 token 估算，不是账单”。
7. **本地存储**：这个渠道在本机的数据目录大小（Codex 是 `~/.codex`，Claude 是 `~/.claude`），按会话、缓存、其他分段（设计稿里写的“日志”以这里为准），写出会话文件数，另有“在访达中显示”按钮。分段规则：会话是 Codex 的 `sessions`、`archived_sessions` 和 Claude 的 `projects`、`sessions`；缓存是两者的 `cache`，加上 Claude 的 `file-history`；其余都算其他。只统计文件大小，不读取任何文件的内容（目录里有 `auth.json` 这类凭据文件）。**不提供删除功能**。统计在后台进行，每次打开额度页时如果距上次统计超过 10 分钟，就重新统计。

## 网络页

MeowMac 自己画，不嵌入 TunCanary 的弹窗。数据来自 TunCanary 的 `AppModel`：`overall`、`local`、`siteHistory`、`egressResults`、`lastCheckedAt`。

1. **结论**：32pt 的状态图标、结论文字、说明（DNS 是否走代理、几项检查通过、检查时间），以及“立即复测”按钮，按钮调用 `MonitorController.recheck()`。
2. **检查项**：一张玻璃卡片，5 行：代理 TUN、VPN、主网络 DNS、代理 DNS、Tailnet。每行是状态点、名称和一句说明。
3. **站点连通性**：按分组显示成 3 个指标块，每块是分组名、通过数和延迟中位数。
4. **出口 IP**：每个探测目标一行，写 IP、地区和稳定天数。

如果某个字段在 TunCanary 外面读不到，就跳过这一项，写进 result；不要修改 TunCanary。

## 底部操作栏

左边是“刷新”（带图标），中间是额度数据的时间，右边是“设置”按钮（带齿轮图标和下拉箭头）。点“设置”弹出的菜单见 `Settings.dc.html`：打开配置文件…、在访达中显示配置目录、猫配置（v0.2 前置灰）、开机启动（打勾开关）、关于 MeowMac、退出 MeowMac（⌘Q）。

## 菜单栏猫

猫的矢量路径以 `MenuBar.dc.html` 里 `run()` 和 `lying` 的定义为准，画布坐标是 44×28，菜单栏里的高度为 18pt。

| 状态 | 图 | 动画 |
| --- | --- | --- |
| 正常 | 5 帧奔跑，模板图，跟随菜单栏深浅色 | 帧间隔随负载在 0.5 秒到 0.05 秒之间变化 |
| 提醒 | 同样的 5 帧，**整只猫为 `systemOrange`**，彩色图 | 速度仍然只看负载，不因为提醒而加快 |
| 严重 | 趴姿单帧，`systemRed`，彩色图，头上有“zz” | 停止 |

负载不低于 0.7 时，在猫身后画三道速度线，颜色和猫一致，正常和提醒状态都适用。规则是：颜色表示状态，速度表示负载。

## 视觉验收

执行者要用 `MEOWMAC_RENDER_DIR` 渲染出下面这些预览图，逐张和设计稿对照，发现不一致就修改，然后重新渲染，直到一致为止：

- 系统页、额度页、网络页、提醒状态，浅色和深色各一张；
- 额度页用 Claude 和 Codex 各渲染一次；
- 菜单栏猫：5 帧，外加提醒和严重。

对照时逐项检查：

1. 元素的顺序和分组与设计稿一致，没有多出或缺少的元素。
2. 尺寸、间距、圆角与设计稿的偏差不超过 2pt。
3. 字号和字重符合本文的字号表。
4. 360pt 宽度下没有文字被截断、重叠或溢出。
5. 系统页在 720pt 高度内，能完整看到联动图和能耗排行。
6. 深色模式下所有文字都清楚可读。
