# MeowMac 路线图

MeowMac 分四个阶段推进。每个阶段都有一个 relay 目录，放执行细节；每个阶段结束都由用户验收，通过后才开始下一阶段。决策的依据见 `docs/DECISIONS.md`。

| 阶段 | 状态 | relay 目录 |
| --- | --- | --- |
| v0.1 能用 | 第 1 轮已执行，复审未通过（界面不合格） | `docs/plans/2026-09-29-meowmac-v0-1/` |
| v0.1 视觉返工 | 第 4 轮已交付，复审收工，待用户实机验收 | `docs/plans/2026-09-30-meowmac-v0-1-ui/` |

| v0.4 机场 | 未规划 | |

## v0.1 能用

目标是回答一个问题：系统、额度和网络三类状态，放在一个菜单栏面板里是否好用。

内容：代码画的临时猫、总览条、三个标签页、底部操作、系统采集、能耗诊断、联动图、4 个渠道的额度和花费、嵌入 TunCanary、清理入口。布局和选项先写死默认值。

用户验收时看的问题：

- 三类状态放在一个面板里，是否拥挤，是否需要来回切换。
- 猫的速度和形态是否一眼能看懂。
- 能耗诊断能不能发现 `BTLEServer` 那类失控进程。
- 额度数据最多滞后 30 分钟，是否可以接受。

验收通过后，用户退出独立运行的 TunCanary，关闭它的开机启动（D23）。

## v0.2 年糕

内容：猫配置体系（`年糕.cat/`）、布局和样式配置、自定义帧图导入、一次性导入 CodexBar 的额度历史。

开始规划前要和用户确认：

- 帧图规格：单色模板图还是彩色图、尺寸、每档几帧。
- AI 绘制和导入帧图的流程。
- v0.1 用下来，哪些选项真正需要做成可配置。

## v0.3 传感器

内容：通过 SMC 或 IOHID 读取 SoC 温度和风扇转速，放在一张实验卡片里；联动图加上这两条线；风扇转速触发的降温提示。

风险：私有接口会随芯片换代失效。参考 exelban/stats（MIT）的实现。

## v0.4 机场

内容：机场订阅额度卡片，通过 D21 的可插拔接口接入。

开始规划前要和用户确认：数据从哪里来，订阅链接等凭据存在哪里。凭据不能进入仓库，也不能进入猫配置。
