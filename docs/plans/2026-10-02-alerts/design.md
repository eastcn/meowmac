# 提醒功能草稿

## 范围与已定偏好

本轮补充提醒管理。任务状态只由同目录的 `plan.md` 维护。用户已确认本方案、交互稿与对话内预览，并授权实施；本文的推荐细节按已确认方案执行。

用户已确定以下偏好：

- 可消除类型：额度不足、额度偏快、磁盘不足和数据源失效。
- 可消除提醒点“我已知道”后，暂缓提醒并退出猫的告警判定。问题仍可查看。
- 严重故障、持续高 CPU、内存压力和系统降频保持提醒。检测恢复后消除。
- 到期仍未恢复时再次提醒。用户每次选择时长，可用预设或自行填写。额度可能需要 1、2、3 天，资源类问题可能只需小时。

首版建议集中列出当前 9 类健康告警，以及“建议降温”提示。配置文件错误、导入失败和布局保存失败仍在原来的操作位置呈现。本轮不建操作错误日志或历史通知中心，也不新增 macOS 系统通知。

## 类型与处理

| 类型 | 粒度 | “我已知道” | 恢复依据 |
| --- | --- | --- | --- |
| 额度不足 | 渠道 × 窗口 | 支持限时暂缓 | 新的有效数据确认剩余恢复到阈值内 |
| 额度偏快 | 渠道 × 窗口 | 支持限时暂缓 | 有效数据和完整时间参数确认不会提前用完 |
| 磁盘不足 | 当前采集磁盘 | 支持限时暂缓 | 新的有效采样确认剩余恢复到阈值内 |
| 数据源失效 | 来源 | 支持限时暂缓 | 该来源实际采集成功 |
| 持续高 CPU | 进程 | 不支持 | 有效采样确认不再满足原诊断规则 |
| 持续内存压力 | 系统 | 不支持 | 有效采样确认不再满足原诊断规则 |
| 系统热状态严重 | 系统 | 不支持 | 有效热状态低于 serious |
| 网络红色故障 | 引擎公开故障键 | 不支持 | 新的完整网络检测确认该故障已恢复 |
| 网络黄色提醒 | 引擎公开故障键 | 推荐首版不支持 | 同上 |
| 建议降温 | 系统 | 推荐保留原标记，不支持暂缓 | 有效采样确认不再满足原提示条件 |

健康阈值沿用当前配置。暂缓不改变采集频率、额度刷新策略、原始数值或各页面的实际状态。未暂缓的其他问题仍可使猫变橙或进入严重姿态。

网络从已有公开故障列表提取具体提醒，不修改 TunCanary。同一故障键只显示一条，多个故障不能只保留首要原因。总体为黄或红却缺少具体故障时，保留一条相应级别的总体提醒。

网络引擎已有的系统通知维持原行为。这些通知不属于本轮可暂缓类型，不宣称 MeowMac 的确认操作关闭了引擎通知。

## 列表与入口

推荐采用 [交互稿](../../design/mockups/alerts.html) 的结构。草稿沿用现有字号和状态色；网页的材质模拟不能作为原生材质验收。

- 总览保留最严重问题和原来的详情跳转。状态行下方增加“全部提醒 · N 项”，即使为 0 也能打开。
- 提醒列表在同一弹出面板内打开，宽 360 pt，最高 820 pt。标题和筛选固定，列表超高时滚动。不新增第四个标签页。
- 筛选为全部、系统、额度和网络。列表分“待关注”和“已知晓”；降温单列为“提示”，不参与告警档位。
- 每条显示类型、具体对象、原因、当前值、实际数据时间和处理操作。“查看详情”返回对应标签页；额度项同时选中对应渠道。
- 已知晓项显示到期时间和“恢复提醒”。计数包含当前待关注、已知晓和提示，不包含已恢复问题。
- 返回总览保留之前所选标签页、额度渠道和时间范围。关闭面板后再次打开，从总览进入，按待关注问题选择默认页。
- 排序为严重优先、提醒其次。同级保持系统／额度／网络及对象身份的稳定顺序。数值变化不造成每次刷新重排。

当全部可消除问题都已暂缓，猫回到正常档。总览写“当前无待关注提醒”，并显示已知晓项数，不能写“一切正常”。各页面仍显示实际风险色、数值和采集失败说明。

有建议降温时保留标记；没有其他告警时，猫仍正常。全部检测确认恢复后，总览恢复“一切正常”，列表显示空状态。

交互稿完整演示总览入口、分类、时长选择、恢复提醒、严重故障保留、到期和空状态。逐对象详情定位、降温提示、真实存储和坏文件等需在原生实现中验收，网页不作为这些行为的证据。

## 暂缓时长

推荐点“我已知道…”后，在面板中打开时长选择。取消或关闭选择界面不改变状态；明确点击“暂缓提醒”后才保存并生效。

- 预设：30 分钟、1 小时、4 小时、1 天、2 天和 3 天。
- 自定义：整数数值，单位为分钟、小时或天。技术推荐范围为 1 分钟至 30 天，拒绝空值、负数、非整数和非有限值。
- 额度有未来重置时间时，额外提供“直到本轮重置”。没有可靠重置时间时不提供这项。
- 选择界面显示预计到期的日期和时间，避免把 3 天误看成 3 小时。1 天按 24 小时计算。
- 首次默认选中 1 小时。每次仍需明确确认，不自动使用上次的选择，也不提供批量暂缓。
- 支持在已知晓列表提前恢复。恢复后立即参与总览与猫的告警判定。

本方案没有永久忽略、关闭某类监测或“一键全部已读”。这些操作的范围另行规划。

## 身份、到期和恢复

提醒身份使用结构字段，不用文案、剩余百分比或行号。例如额度为类型、渠道和窗口标识；数据源为类型和来源。数值更新不会产生新提醒。

以下规则是推荐，随草稿一并确认：

1. 同一持续问题的暂缓保存绝对到期时间。重复刷新不延长到期；重启、休眠和关闭面板也不重置。
2. 到期时问题仍存在，重新进入待关注并参与猫判定。唤醒或重新启动时先核对到期，无须打开列表。不为再次提醒增加实时额度请求。
3. 检测确认恢复后，移出当前列表并删除对应暂缓记录。之后同类问题重现，属于新问题，立即提醒。
4. 额度重置周期变化时，旧周期的暂缓不沿用。选择 3 天也只暂缓当前问题，不覆盖新周期；选择界面应明确说明。重置信息缺失或无法确认周期变化时，不凭猜测清除暂缓。
5. 问题升级为严重时，立即取消暂缓。提醒降级不能抹掉原本需要持续显示的诊断。
6. 采集失败、字段缺失、未知状态和网络检测尚未完成均不等于恢复。保留最后已确认的问题，并注明数据时间或“待确认”；数据源失效作为独立提醒。
7. 正常过期数据不能建立新的额度周期。历史缓存用于展示时，必须保留采集时间，不能把上轮缓存冒充本轮数据。
8. 首版不保存已恢复历史，不提供删除历史或导出。需要历史中心时另行定义保留期限和隐私范围。

## 保存与失败

暂缓属于本机提醒管理，不随猫配置切换，也不写入可分享的 `.cat` 包。保存位置限定在 MeowMac 自己的应用支持目录。实际文件合同在定稿后的实施清单中固定。

建议只保存类型、对象键、已确认时间、到期时间和必要的额度周期标识。不要保存原始错误文本、邮箱、IP、进程路径、凭据或网络明细。首次无暂缓记录时不生成默认文件。

本轮文件合同：应用支持目录下的 `reminder-snoozes.json`。顶层为 `schemaVersion: 1` 和 `records`。记录包含 `key`、`kind`、`acknowledgedAt`、`until` 和可选 `cycleResetAt`，日期为 Unix 毫秒。最多 64 条、64 KiB，拒绝未知字段、重复身份、坏版本和非普通文件。只保存可暂缓类型；网络明细不写入此文件。额度周期抖动容差复用现有额度历史的 10 分钟，不把重置时间的小幅变化当成新周期。

- 保存成功后才改变猫和列表；失败时保留待关注状态，明确显示“暂缓未保存”。
- 主动恢复失败时，不把磁盘中的暂缓记录误报为已移除。到期与严重升级仍按当前事实生效，不能因写盘失败继续隐藏风险。
- 坏文件不当作“全部已知晓”。回退为没有暂缓，保留原文件并显示恢复说明；正常显示所有仍存在的问题。
- 路径、普通文件和符号链接检查沿用现有本机存储边界。测试使用注入的合成目录，不读写真实配置。

## 实施建议与验收

实施分为以下 3 项。实时进度以 plan 为准，本文保留责任范围和验收依据。

| 条目 | 责任范围 | 验收依据 |
| --- | --- | --- |
| 提醒模型与暂缓存储 | Core 的结构化身份、分类、暂缓和恢复；本机存储遵守项目分层 | 生产规则入口配合合成时钟和注入目录，覆盖独立对象、到期与写入失败 |
| 原生列表与时长选择 | UI 总览入口、同面板列表、筛选、详情定位、时长和恢复 | 真实 SwiftUI／AppKit 容器；360 pt，最高 820 pt；对照确认后的稿件 |
| 运行时集成与验收 | 真实初始化、采样更新、唤醒、猫切换与快照；离线和用户实机验收 | `scripts/check.sh`、`scripts/build-app.sh`，合成截图放 `build/acceptance/`；安装另获授权 |

必要验收至少覆盖：

| 场景 | 应看到的结果 |
| --- | --- |
| 多类型、多渠道、同渠道多个窗口 | 全部可见，身份独立，重复刷新不增加条数 |
| 两个可消除提醒，只暂缓一个 | 该条移入已知晓，另一条仍使猫提醒 |
| 全部可消除提醒暂缓 | 猫正常，总览说明有已知晓问题，原始数值和错误提示仍在 |
| 同时有严重故障或持续能耗异常 | 相应行没有暂缓入口，猫继续按剩余最高档显示 |
| 选 2 天或自定义 3 天 | 到期时间正确；确认后生效，取消不写入 |
| 空值、负值、小数、超范围 | 拒绝保存，当前提醒保持不变 |
| 到期仍有问题／到期前已恢复 | 前者重新提醒；后者移出列表，不制造空告警 |
| 重启、切猫和睡眠跨过到期 | 暂缓范围独立于猫；未到期保留，已到期恢复提醒 |
| 恢复后重现、额度换周期、升级严重 | 作为新问题或更高风险立即提醒，旧暂缓不沿用 |
| 来源失效、字段缺失和未完成检测 | 不误报恢复；显示数据时间或待确认 |
| 保存失败、坏文件和符号链接 | 不虚报暂缓成功，不误隐藏现有风险；包外哨兵不变 |
| 浅色／深色、多行文本和长列表 | 控件可完整点击，字号和状态色符合 SPEC；高度不超过 820 pt |

离线测试不能代替原生材质、真实点击、长列表滚动和重启的用户实机验收。真实数据截图和原值只放在忽略的 `build/acceptance/`。
