## 决策点

类型：`偏好`（执行者不能改）、`技术`（执行者可凭证据更正或提异议）、`安全`（只能收紧）。

| 编号 | 类型 | 问题 | 结论 |
|---|---|---|---|
| D1 | 偏好 | 呈现范围 | 已定（用户 2026-10-25）：只显示状态，外加结束提示。不做等批准、跳转和气泡内交互。 |
| D2 | 偏好 | 指标形态 | 已定（设计稿 2026-10-25 用户确认）：目录新增“AI 会话”一类，只有一项，id 为 `agent.sessions`。标签“AI 会话”；数值是两个渠道**已确认在跑**的主会话总数，写成“3 在跑”；没有在跑时写灰色“空闲”；两个渠道的根目录都读不了时写“—”。不画横线。悬停提示写分项和数据时间，例如“Claude 2 个在跑，Codex 1 个 · 14:02 更新”；有状态未确认的会话（D7）时追加“另有 n 个未确认”，未确认的不计入数值（预审 P4）。某个渠道没安装就不写这一项。默认指标不变。 |
| D3 | 偏好 | 结束提示 | 已定（用户 2026-10-25，设计稿同日确认）：只在选了 `agent.sessions` 时提示。玻璃胶囊，高 24 pt，最宽 220 pt，与气泡同侧对齐。<br>**下方两个角**：提示在气泡上方 6 pt，新的贴着气泡。<br>**上方两个角**：提示在猫下方 6 pt，新的贴着猫。原因：上方的角气泡顶着可见区域上沿，上面放不下（预审 P1）。<br>文字是“✓ 名称 · 渠道 · 已完成 · 耗时”，11 pt。最多叠 2 条，更多时离猫远的那条改成“另有 n 个会话完成”。点提示只关这一条，不开面板；5 分钟后自动消失。名称取会话标题，没有就取项目目录的最后一段，过长在末尾截断。耗时格式和面板现有的时长格式一致。不发系统通知。 |
| D4 | 偏好 | 刷新节奏 | 已定（用户 2026-10-25）：桌面猫开着且选了 `agent.sessions` 时，没有会话在跑每 60 秒检查一次，有会话在跑每 10 秒检查一次。其他时候完全不读会话记录。休眠和屏幕休眠时暂停，唤醒后立即检查一次。D8 的额度扫描保持原样，两者不共用计时器。 |
| D5 | 技术 | “在跑”和“结束”的判定 | 允许默认：<br>**Claude**：主会话文件里最后一个非子 Agent 的 `assistant` 行，其 `stop_reason == end_turn`，并且之后没有新的 `user` 行，就算本轮结束；否则算在跑。<br>**Codex**：最后一个 `task_started` 之后有对应 `turn_id` 的 `task_complete` 就算结束；否则算在跑。<br>两种渠道都一样：文件超过 10 分钟没有写入，算已停止，不计数，也不提示。用户中断（Claude 的中断标记，或 Codex 没有 `task_complete` 就停止写入）不提示。<br>执行者核实真实形态后可以更正判定字段，更正要在 result 里写明证据，证据只写字段名。 |
| D5a | 技术 | 结束的识别（预审 P3） | 允许默认：每次结束带一个完成标识：Codex 用 `task_complete` 的 `turn_id`，Claude 用 `end_turn` 那一行的 `uuid`。按会话记下“已处理的完成标识”。某个会话读到的最新完成标识和它记下的不同，并且完成时间不早于协调器开始运行的时间，就产生一次提示，再更新记录。判断不依赖上一次检查的时间，所以因为读取预算延后一轮才读到的完成，也只会晚一点提示，不会丢（第二次预审 P3）。两次检查之间完整跑完一轮、新会话在两次检查之间开始又结束，也能提示。协调器开始运行之前就完成的轮次只记录，不提示。同一完成标识只提示一次。 |
| D6 | 技术 | 主会话与子 Agent | 允许默认：Claude 的 `subagents/` 目录下的文件、`isSidechain == true` 的行不算独立会话；子 Agent 文件的写入时间计入所属主会话，用于 10 分钟判定。Codex 的 `session_meta.parent_thread_id` 非空，或者 `agent_role` 表明是子 Agent 的线程，合并到父线程。核实不到父子关系的线程按独立会话计数，并在 result 里说明。 |
| D7 | 技术 | 读取方式与成本 | 允许默认：<br>**列文件**：每次检查只看修改时间。Claude 递归扫描（同 `AgentActivityScanner`）。Codex 扫描**全部**日期目录，因为旧日期目录里的会话恢复后会继续写入（预审 P2）。Codex 的目录列表按目录修改时间缓存，没变的目录不重新列。D8 原有的“最新 3 个日期目录”规则不改。<br>**解析**：只解析 10 分钟内有写入的文件。按（路径、大小、修改时间）缓存每个文件的解析结果，没变的文件不重读。每个文件最多读末尾 64 KB，丢掉第一行不完整的部分和末尾没写完的一行，坏行跳过。<br>**未确认**（预审 P4）：末尾 64 KB 里找不到判定依据，或者因为超出读取预算还没读过，状态记为“未确认”，不计入在跑数，也不提示，按 D2 写进悬停提示。每次检查最多新读 20 个文件，从新到旧；没读到的下次接着读，有缓存的文件不占预算。<br>**Codex 开头元数据**：`session_meta` 在文件开头，每个文件只在第一次见到时读开头一行。读到的标题、目录和父线程按路径和 inode 缓存，文件消失时清掉。<br>不跟随目录内的符号链接，不写任何文件。文件读取放在后台队列，不阻塞主线程。 |
| D7a | 技术 | 实机取证（预审 P6） | 允许默认：会话协调器在计数、未确认数或扫描状态变化时，用 `Logger` 记一条 `.notice` 日志（subsystem 为 bundle id，category 为 `agent-sessions`）。日志只含数字和状态，例如 `claude=1 codex=0 unknown=0 state=ok`，不含路径、标题和目录名；数字字段标 `privacy: .public`。不写额外文件。另外**每次检查**记一条 `.debug` 日志：检查序号、完成时间、各渠道计数、未确认数和扫描状态，同样只含数字（第二次预审 P9）。`.debug` 不落盘，只在实时流里看得到。第 3 轮执行者在测量窗口内后台运行 `log stream --level debug --predicate 'subsystem == "io.github.eastcn.meowmac" AND category == "agent-sessions" AND processID == <被测 pid>'`，输出写到 `build/acceptance/desktop-cat-sessions/`。取证要求：序号连续，相邻两次间隔不超过 15 秒，在跑数始终大于 0，状态始终正常。有任何一条不满足，这项验收就不通过。 |
| D8 | 安全 | 隐私 | 已定：只取类型、时间戳、`stop_reason`、`turn_id`、`uuid`、标题、`cwd` 的最后一段和父子关系。消息正文、工具输入和输出、提示词一律不进内存模型，也不写日志。除 D7a 的数字日志外，日志都用 `privacy: .private`，而且不带路径、标题和目录名。会话状态不写历史文件，也不进 `config.json`。测试夹具全部虚构。 |
| D9 | 技术 | 分层 | 允许默认：<br>判定是纯函数，放 `MeowMacCore`，输入一段日志文本或解析过的行，输出会话状态。<br>提示的生成也是纯函数：比较前后两次快照的完成标识（D5a）。<br>文件读取放 `MeowMacQuota`，和 `AgentActivityScanner` 放在一起，但不改它的行为。<br>节奏和界面放 `MeowMacUI`。 |
| D10 | 技术 | 版式实现 | 允许默认：结束提示放在桌面猫同一个窗口里，`DesktopCatLayout` 增加提示区的高度和宽度。窗口仍然贴住所在的角：下方的角提示在气泡上方，窗口向上长；上方的角提示在猫下方，窗口向下长。两种情况下猫和气泡相对屏幕的位置都不变。提示的命中区域并入点击穿透判断。提示出现和消失时，窗口改变大小不能抖动。 |
| D11 | 偏好 | 目录与菜单 | 已定：右键菜单的“指标 ▸”和设置里的“添加指标…”在网络之后新增“AI 会话”分组，只有一项。两个渠道的根目录都不存在（没装）时不列这一项；已选但不在目录里时按 D45 显示“—”。 |
